02Getting it onto the Mac

Three routes, cheapest first. Route A is enough for most days. Route B is the one that gives you a real Dock icon and its own window with no browser chrome around it.

A

Just open it

Double-click index.html. Every link on this page is relative, so the whole desk works straight off the disk with no server running.

The only thing you lose is offline caching, which you do not need when the files are already local.

B

Install it as an app

Double-click Open Director Bible.command. It starts a small local web server in this folder and opens the desk in your browser. First run only: right-click it → Open, because macOS blocks double-clicked scripts the first time.

Then in Chrome or Edge, File → Install page as app (or the install icon in the address bar). You get Production Desk in the Dock, in its own window, and it keeps working after you close the terminal because the service worker has cached everything.

C

Or run the server yourself

In Terminal, from this folder: python3 -m http.server 8733 — then open http://localhost:8733. Same result as B, without the launcher file.

—

Where your work is actually stored

Run-sheet progress, ticked checks and vault keys live in browser local storage, which is per-browser and per-origin. That has one consequence worth knowing before you start: opening the bible from a file path and from localhost are two different origins, so they keep two separate sets of progress.

Pick one route and stay on it. If you plan to install it as an app, start with route B from day one.

04Before you start work

Three screenshots, same three every day, in this order. It takes about forty seconds and it is what lets the project be read back accurately instead of remembered optimistically.

Shot 1Folder tree, expanded Every folder open, asset counts visible. This is the one that shows drift.
Shot 2All assets, filtered to Liked The favourites are the shortlist. If it is not liked, it does not exist yet.
Shot 3Elements → Characters Handles and their image counts, so identity drift is caught the day it starts.
STANDUP  — paste this above the screenshots

Date:        2026-__-__
Gate:        A / B / C / D / E        (last one that HOLDS)
Yesterday:   ______________________
Today:       ______________________
Blocked by:  ______________________  (or: nothing)
Counts:      refs __/43   anchors __/39   shots __/23
  • Full window, never a region. A cropped screenshot hides the thing that was about to be the answer.
  • One screen per image. Two monitors in one file makes both unreadable.
  • Never scale down on export. Filenames and counts are the payload; if they are not legible the capture was wasted.
  • Same three, same order, every day. The value is in the diff, and a diff needs the shots to line up.
On the name crosswalk. The table mapping production names back to the novel is deliberately not inside director-bible.html. It lives in crosswalk.local.js, which is gitignored and never committed. If that file is sitting in this folder the table appears in the bible's rights section; if it is not, there is nothing there to leak. That is the correct state for any copy you publish, share or push.
