# Filing list — what belongs inside the submission project

Generated by `design/filing-list.py`. Do not hand-edit; re-run it.

## The rule, and why nothing here is automatic

Every asset used in the film has to sit inside the submission project, because that is how the generation history verifies the film. **The API cannot put it there.** Checked four ways: one private workspace with no project target; a `folder_id` parameter that exists only on `minimax_h3` and `minimax_h3_max`, only at the moment of generation, and on no image model; no call anywhere to list folders, create one, or move a finished generation; and no marketplace app that exposes one. So this is a list to work down by hand in the web app, and it is regenerated rather than remembered.

## How to work it

1. Open the generation history in the web app.
2. Work down **The film's own assets** below. Each row names the handle, frame or shot it is, so a row you cannot find is a real problem, not a typo.
3. Leave everything in **Recent, but not in the film** where it is. The project is read as the submission; exploration inside it only muddies that.
4. Record the date you finished as `filing.filed_through` in `design/gates.json`, then re-run `python3 design/verify-steps.py` — step 34 checks the two against each other.

A row marked ◆ is a creature shot.
